# 04. 실습 프롬프트

교육 당일 Claude Code 또는 Codex에서 `프로젝트/` 폴더를 연 뒤 아래 요청을 순서대로 사용합니다. 그대로 복사해도 되고 자신의 표현으로 바꿔도 됩니다.

## 1. 프로젝트 파악

> 이 프로젝트의 폴더와 파일을 읽고 무엇이 들어 있는지 설명해줘. 아직 파일은 수정하지 말고, 원자료의 형식과 서로 충돌할 수 있는 정보부터 알려줘.

## 2. LLM Wiki 만들기

> `raw-data/`의 자료들로 LLM Wiki를 만들어줘. 결과는 `wiki/`에 Markdown 파일로 저장하고, 각 페이지에 사용한 원문 파일명을 남겨줘. 기관·지역·사업·활동·위험·의사결정 사이의 관계를 링크로 연결해줘. 원문에 명시된 관계와 네가 추론한 관계는 구분해줘.

## 3. 근거를 붙여 답하기

> 이 사업의 대상 지역 수, 예산, 핵심 위험을 설명해줘. 자료마다 내용이 다르면 하나로 단정하지 말고 차이와 출처를 함께 보여줘.

## 4. Lint와 Bookkeeping 맡기기

> Wiki를 점검해줘. 깨진 링크, 고립된 페이지, 중복 페이지, 출처 없는 주장, 서로 충돌하는 수치, 갱신이 필요한 페이지를 찾아 목록으로 남겨줘. 안전하게 고칠 수 있는 것은 고치고 변경 내용을 설명해줘.

## 5. 주관적 관계 추가하기

> `raw-data/07-후속아이디어.md`는 사용자가 직접 적은 생각이다. 이 문서가 관련된 Wiki 페이지를 연결하되, 객관적 사실이 아니라 사용자 작성 관계라는 점을 명시해줘.

## 6. 반복 절차를 Skill로 만들기

> 내장된 `skill-creator`를 사용해서 방금 수행한 Wiki 답변·근거 확인 절차를 반복 가능한 Skill로 만들어줘. 다른 질문으로 시험하고 부족한 규칙을 보완해줘.

## 7. 보안 검토 습관

> 이 프로젝트의 보안 취약성을 검토해줘. 중요도순으로 설명하고 수정안을 제시해줘. 외부 업로드, 비밀정보, 개인정보, 공개 저장소에 포함하면 안 되는 파일을 특히 확인해줘.

## 8. Git에 첫 기록 남기기

> 현재 프로젝트에서 Git으로 관리할 파일과 제외할 파일을 구분해줘. `.gitignore` 초안을 제안하고, 내가 확인하기 전에는 커밋이나 원격 푸시를 하지 마.

## 선택: 웹앱 계획

> 지금 만든 Wiki를 브라우저에서 검색하고 탐색할 수 있는 작은 웹앱을 계획해줘. 사용자는 누구인지, 어떤 문제를 해결하는지, 필요한 데이터와 최소 기능, 검증 방법을 먼저 정리하고 아직 코드는 수정하지 마.
